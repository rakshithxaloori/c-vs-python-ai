Seven engines.

One AlexNet-shaped convolutional network (5 conv + 3 fully connected layers, parameters) was trained from the exact same starting weights, on the exact same images in the exact same order, by seven implementations: four driven by Python, three written in C. Each got the same 60-second training budget.

Three separate effects hide inside "C vs Python"

The hot loop

The same five lines, two languages

This is the innermost loop of the convolution in python/pure_python.py and c/alexnet.c. The algorithm is identical. In C each line compiles to a few machine instructions. In CPython each += becomes a run of bytecodes: two list lookups, a float multiply that allocates a new object, and a float add that allocates another.

Sanity check

They really are computing the same thing

Training loss after each of the first three SGD steps (batch 4), starting from the shared initial weights. Agreement to about six significant digits means any speed difference comes from how the math is executed, never from what is computed. The tiny differences come from float32 vs float64 and the order of additions.

The contestants

What each engine actually is

The same C source file builds all three C binaries. Fast Python, meaning NumPy and PyTorch, is Python handing work to compiled C, C++ and assembly. NumPy here calls Apple Accelerate for matrix multiplies, the same library the C + BLAS build links against.

Method

Reproduce it

The dataset is 4,096 training and 1,000 test images (32×32 RGB, 10 procedurally drawn shape classes), generated locally with a fixed seed, so nothing is downloaded. Implementations run one at a time so they never compete for the CPU. Snapshot saving is excluded from the training clock. Pure Python runs only a couple of SGD steps in its minute, so its curve barely leaves the starting point.
